# ClipHarbor · 拾贴：快捷短语功能设计

日期：2026-10-08
状态：两端客户端及服务端已实现；构建和部署由 CI 校验，双设备实机验收待验证
适用平台：macOS、Windows
已确认的方向：我们提供预置短语，用户根据自己的账号维护个人短语

第一版采用“官方预置短语 + 账号个人短语”。预置短语让用户开箱即可使用；用户登录后可以新增个人短语，也可以基于预置短语保存自己的版本。个人内容属于当前账号，同一账号的设备同步，不影响其他用户。

当前按“打开面板，搜索并复制／粘贴短语”设计。输入缩写自动替换、模板变量等仍为后续建议。本机保存用于账号短语的离线缓存，第一版不另设无账号的自定义短语库。

## 1. 功能定位

快捷短语是一份可以快速取用的固定文本库，适合日常回复、工作沟通、邮件签名、地址及代码片段等场景。

典型流程：在聊天输入框中 → 唤起拾贴 → 进入“短语” → 搜索“收到” → 使用预置的“确认收到”。用户也可以点击“自定义”，改成符合自己习惯的回复，保存到自己的账号后反复使用。

| 功能 | 内容来源 | 主要用途 | 保存与清理 |
| --- | --- | --- | --- |
| 历史 | 系统剪贴板自动记录 | 找回复制过的内容 | 遵循历史保留时间和数量限制 |
| 收藏 | 用户收藏历史记录 | 保留重要历史 | 遵循现有收藏策略 |
| 常用 | 本机依据重复复制与使用次数推荐 | 更快找到常用历史 | 依赖历史及本机学习统计 |
| 预置短语 | 我们维护并随客户端提供 | 开箱可用的通用内容 | 跟随预置版本更新 |
| 个人短语 | 当前账号新增、从历史保存或自定义预置内容 | 长期维护自己的固定文本 | 独立保存，仅主动删除 |

**短语与历史独立。** 清空历史、删除原记录、重置常用学习、关闭剪贴板记录，都不删除个人短语；编辑短语不修改原历史，也不修改系统剪贴板。

## 2. 已确认需求与第一版范围

已确认的产品要求：

1. 我们提供一批预置短语，所有用户都能获取和使用。
2. 用户以自己的账号新增、编辑和删除个人短语。
3. 用户可以自定义预置短语，改动只作用于自己的账号。
4. 用户之间的个人内容和偏好互相隔离。

| 优先级 | 能力 | 第一版行为 |
| --- | --- | --- |
| P0 | 官方预置 | 随客户端内置一批中文短语，支持分类、搜索和直接使用 |
| P0 | 个人创建与编辑 | 登录后维护标题、正文、可选检索别名、分组和置顶 |
| P0 | 自定义预置 | 点击“自定义”创建／编辑当前账号的个人版本，保留来源标识 |
| P0 | 从历史保存 | 文本和链接可保存到当前账号的个人短语 |
| P0 | 检索与管理 | “全部 / 我的短语 / 预置短语”、分组、置顶、编辑、删除 |
| P0 | 快速使用 | 面板复制／粘贴，完整键盘导航 |
| P0 | 账号同步与离线 | 同账号设备同步，离线访问已登录账号的缓存与待同步改动 |
| P0 | 个人预置偏好 | 登录用户可隐藏或置顶预置项，偏好按账号同步 |
| P0 | 版本与异常保护 | 官方更新不覆盖个人内容，写入失败保留草稿，处理同步冲突与账号切换 |
| P1 | 预置运营管理 | 服务端管理后台编辑、审核与发布预置版本，无需更新客户端 |
| P1 | 导入导出 | 带版本号的 JSON 备份、批量导入及重复项处理 |
| P1 | 模板变量与批量整理 | 使用时填写字段、日期等；多选移动／删除与拖拽排序 |
| P2 | 输入缩写自动扩展 | 在其他应用键入别名后替换，需要独立设计 |
| P2 | 单条全局快捷键 | 为某条短语注册独立组合键及冲突管理 |

第一版正文为**纯文本**，保留换行、缩进、空行和末尾换行。链接、代码、Markdown、命令都作为普通文字保存；不执行命令、不解析 HTML、不展开变量。图片、文件和富文本模板暂不进入短语库。

## 3. 预置内容与个人自定义

### 3.1 预置短语的维护方式

第一版由项目维护者在版本控制中的统一 JSON 资源维护预置内容，macOS 和 Windows 打包同一份资源。预置内容不复制进每个账号，不占个人短语数量配额，也不需要登录即可使用。

每批资源有 `catalogVersion`；每条预置短语有稳定 `presetId` 和自己的 `presetVersion`。修改正文增加条目版本，新增条目使用新 ID，下架条目从预置列表移除，不复用旧 ID。

运行中的客户端只在完整校验资源后切换目录版本。升级失败保留已有有效版本。第一版预置更新随客户端发布，同一账号的不同客户端可能暂时使用不同预置版本；后续增加服务端发布时再提供独立下载、版本检查和回退能力。

### 3.2 第一批内容示例

以下是建议首批中文内容，供确认和扩充；不包含用户真实姓名、地址、账号信息或需要自动展开的变量。

| 分类 | 标题 | 正文 |
| --- | --- | --- |
| 日常沟通 | 确认收到 | 收到，谢谢！ |
| 日常沟通 | 稍后回复 | 我现在不方便详细回复，稍后联系你。 |
| 日常沟通 | 表示感谢 | 谢谢你的帮助，辛苦了！ |
| 日常沟通 | 礼貌结束 | 好的，感谢沟通，有需要我们再联系。 |
| 工作协作 | 接收任务 | 收到，我会先确认需求，再同步处理计划。 |
| 工作协作 | 补充信息 | 为了准确处理，请补充具体场景、预期结果和相关资料。 |
| 工作协作 | 进度同步 | 目前正在处理中，有进展后我会及时同步。 |
| 工作协作 | 确认时间 | 请确认一下期望完成时间，方便安排后续工作。 |
| 工作协作 | 请求检查 | 相关内容已整理，请帮忙检查；如需调整，请直接指出。 |
| 客户回复 | 问候 | 您好，请问有什么可以帮您？ |
| 客户回复 | 问题反馈 | 收到您的反馈，我会先核实情况，再向您回复处理结果。 |
| 客户回复 | 提供复现信息 | 为了进一步排查，请提供操作步骤、出现时间及相关截图。 |
| 邮件沟通 | 邮件开头 | 您好，感谢您的来信。 |
| 邮件沟通 | 附件说明 | 相关资料见附件，请查收。 |
| 邮件沟通 | 邮件结尾 | 感谢您的时间，期待您的回复。 |

个人地址、姓名和邮件签名由用户自行创建，避免用未经填写的占位文字作为可直接粘贴的预置项。

### 3.3 自定义预置的行为

预置详情提供“复制”“粘贴”和“自定义”。预置正文只读；“自定义”打开以其标题、正文和别名为初始值的个人编辑器，用户保存后创建个人短语，记录 `originPresetId` 和 `originPresetVersion`。

- 同一账号对同一预置项只保留一个关联个人版本；再次点击“自定义”打开已有个人版本，避免重复创建。
- “全部”视图优先展示个人版本，隐藏对应预置项的重复结果；“预置短语”视图仍可查看官方原文，并显示“已有个人版本”。
- “我的短语”展示自建短语、从历史保存的短语和已经自定义的预置短语。
- 用户 A 修改后，用户 B 仍看到官方原文；A 的其他设备同步取得 A 的个人版本。
- 预置分类映射为同名个人分组，优先复用；首次保存时与个人短语一起原子创建，超限时可改为未分组。
- 官方更新或下架不覆盖、不删除已保存的个人版本。原预置不存在时，个人短语仍正常使用，来源显示“原预置已下架”。
- 个人版本可显示“预置有更新”，供查看新版。用户显式选择“恢复预置正文”并确认后，才替换正文和来源版本；保留个人标题、别名、分组及置顶。
- 删除关联个人版本后，“全部”重新展示当前预置版本，除非用户已经隐藏该预置项；删除确认文案说明这一结果。
- “复制一份”生成不关联预置的新个人 ID，允许用户另存多个不同变体；它不占用唯一的关联个人版本。

## 4. 入口与界面

### 4.1 管理入口

- 历史窗口侧栏增加“快捷短语”，与“收藏”“常用”并列。
- macOS 菜单栏／Windows 托盘菜单增加“打开快捷短语”。
- 文本／链接历史的“更多操作”和右键菜单增加“保存为个人短语”；图片和文件不展示此操作。
- 设置增加短语同步状态及“打开短语管理”。短语页面显示当前账号；未登录时展示预置内容及登录入口。

管理页沿用 macOS 的 SwiftUI / Liquid Glass 和 Windows 的 WinUI 3 / Fluent。下图仅表示信息结构。

```text
快捷短语 · 当前账号               搜索标题、别名或正文…        ＋ 新建
┌─────────────┬─────────────────────┬──────────────────────────┐
│ 全部         │ ★ 我的确认回复      │ 我的确认回复             │
│ 我的短语     │   收件地址          │ 来源：自定义“确认收到”    │
│ 预置短语     │   邮件签名          │                          │
│ 置顶         │   请求检查 · 预置   │ 收到，我会在今天处理。    │
│ 未分组       │                     │                          │
│ 工作协作     │                     │ 复制  粘贴  编辑  更多    │
│ 日常沟通     │                     │ 已同步 / 待同步           │
└─────────────┴─────────────────────┴──────────────────────────┘
```

默认进入“全部”，每条记录标注“预置”或“我的”，自定义后的个人版本显示来源。预置分类由我们维护，个人分组由账号维护；筛选时标明来源，同名分类可合并展示。“未分组”是个人短语的系统视图，不创建为可删除实体。

### 4.2 快捷面板

- 现有快捷面板增加“历史 / 短语”切换，普通唤起继续进入历史。
- “打开快捷短语”入口直接进入短语视图并聚焦搜索。
- 复用现有全局唤起键：macOS 默认 `⌥⌘V`，Windows 默认 `Ctrl + Alt + V`。
- 新增“直接打开短语面板”操作，默认不分配组合键；用户可录制，沿用冲突检查。Windows 需增加第二个全局操作的注册与录制能力。
- 列表展示标题、一行正文摘要、置顶状态和来源；详情查看完整正文。
- 无结果显示“没有匹配的短语”。首次使用直接展示预置内容，登录后可创建个人短语。

### 4.3 新建与编辑

新建个人短语需要登录。编辑器包含标题、正文、检索别名、个人分组、置顶及“保存 / 取消”，顶部明确“保存到当前账号”。“自定义”预置时另外展示来源；账号归属不可在编辑器中任意指定。

正文允许多行输入，`Enter` 换行，`⌘S` / `Ctrl+S` 保存。保存成功才关闭编辑器；取消或关闭存在改动的编辑器时提示是否放弃，写入失败保留全部输入。

已登录账号断网后可使用缓存并新增／编辑个人短语，改动持久化并标记待同步。未登录或账号身份尚未确认时，不能创建个人短语；点击新建／自定义／从历史保存引导登录，成功后返回原操作。

从历史保存时取文本表示，富文本只取纯文本；标题建议取首个非空行并截断到上限。保存为独立个人短语，不与原历史绑定生命周期。

## 5. 使用、搜索与管理规则

### 5.1 复制与粘贴

| 操作 | 行为 |
| --- | --- |
| 单击 | 选中短语并展示正文 |
| 面板列表按 `Enter` | 复用“选择后自动粘贴”设置；默认复制，开启后尝试粘贴 |
| 管理页列表按 `Enter` | 复制，不隐式切换应用 |
| 双击／点击“粘贴” | 复制后尝试粘贴到唤起拾贴之前的应用 |
| 点击“复制” | 仅复制；面板关闭并恢复原应用，管理页保持打开 |
| macOS 未授权辅助功能 | 复制成功，提示可手动粘贴及所需权限 |
| Windows 目标窗口权限阻止输入 | 保留已复制正文，提示手动 `Ctrl+V` |
| 目标窗口失效或焦点发生变化 | 不向其他窗口发送粘贴，保留手动粘贴能力 |

仅在系统剪贴板写入成功后增加使用次数，该次数表示成功复制，不宣称已确认目标应用收到文字。失败、预览、搜索和保存不计数。

主动使用短语不额外生成本机历史，也不增加“常用”学习统计。两端抑制自身写入被监测器再次捕获；是否发布跨设备复制事件另按现有文本同步规则处理。

### 5.2 键盘导航、搜索与排序

- 搜索框直接输入检索，`↓` 进入列表，上下键选择，`Enter` 使用。
- `Tab` / `Shift+Tab` 遍历筛选、搜索、列表、预览及操作按钮；`⌘F` / `Ctrl+F` 聚焦搜索。
- `Esc` 依次退出子弹窗、清除搜索、关闭面板；编辑器保留中文输入法组合、多行回车与文本系统操作。
- 搜索匹配标题、别名、正文和分类／分组名称，不区分英文大小写；查询去掉首尾空白，按空白拆词，所有词均需匹配。
- 中文按子串匹配，第一版不做拼音、语义搜索或 AI 推荐。
- 别名如 `ack` 仅用于搜索；搜索 `/ack` 可忽略一个前导 `/`，不在其他应用自动替换。
- “全部”先对同一 `originPresetId` 应用个人版本优先规则，再过滤和排序，避免旧官方正文产生重复搜索结果。
- 无搜索时：置顶优先 → 本机最近使用时间降序 → 标题 → ID 稳定排序；有搜索时标题／别名完全匹配、前缀、其他字段包含依次优先。
- 使用统计留在本机，排序可因设备不同而不同；个人内容、置顶和预置隐藏偏好按账号同步。
- 排序变化保持当前选中 ID；远端删除或切换账号使选中项失效时取消选择，避免回车使用另一项。

### 5.3 删除、隐藏与分组

个人短语删除需要确认，并提示会从此账号的其他设备删除。第一版不提供回收站；未保存草稿仍需保护。

预置项没有用户“删除”操作。登录用户可“隐藏这条预置短语”，仅作用于自己的账号；提供“显示已隐藏”和“恢复显示”。隐藏不删除对应个人版本，不影响其他账号；未登录只可查看／使用预置内容。

个人分组支持单层创建、重命名和删除，每条个人短语最多属于一个分组。删除分组只将内容移到未分组，确认文案显示数量；预置分类不能由普通用户修改或删除。

标题可重复；同一账号内个人短语的非空别名不区分大小写且唯一。预置别名不占个人唯一性约束；自定义时如遇个人别名重复，提示修改或清空，不能静默覆盖已有短语。

## 6. 账号、同步与预置更新

### 6.1 内容及权限边界

| 内容 | 未登录用户 | 当前账号用户 | 维护方 |
| --- | --- | --- | --- |
| 预置短语原文与分类 | 可查看、搜索、使用 | 可使用、查看原文、自定义为个人版本 | 在资源中维护并发布 |
| 个人短语与分组 | 不可访问 | 只能维护自己的内容 | 不经普通接口跨账号修改 |
| 预置隐藏／置顶偏好 | 不开放持久化修改 | 只修改自己的偏好 | 不改变统一预置原文 |

个人库只展示当前已确认登录的账号内容。所有服务端个人数据操作从会话取得 `account_id`，不能相信客户端传入的账号 ID。个人短语数量和内容不会因为某条预置原文更新而被全局改写。

### 6.2 同步开关与剪贴板事件

个人短语默认随已登录账号同步，依赖现有总开关“自动同步”。“同步快捷短语”默认开启，用户可以单独暂停；它独立于“同步文本／图片／文件”类型开关。新建和保存界面明确内容会保存在当前账号并同步至其设备。

| 行为 | 更新个人库或偏好 | 写入本机剪贴板 | 发布跨设备复制事件 |
| --- | --- | --- | --- |
| 创建、编辑、分组、置顶、删除、隐藏预置 | 是，按同步开关上传 | 否 | 否 |
| 收到远端个人变更或官方资源更新 | 是 | 否 | 否 |
| 主动使用预置或个人短语 | 仅更新本机使用统计 | 是 | 按现有文本同步规则处理 |

主动使用短语可在总同步及文本同步开启、会话在线时走现有文本复制事件通道。为兼容现有事件协议，服务端可能建立对应文本历史记录，但不保存标题、分组或预置来源；该历史与短语实体独立。未登录则仅写入本机剪贴板。

接收设备关闭“跨设备直接粘贴”时继续按现有规则只接收历史。关闭短语同步暂停个人库上传／下载，不删除缓存、不改变账号归属；允许本地读写并标记待同步，恢复后先取得服务端版本再提交操作。全局暂停记录不阻止主动使用短语。

### 6.3 账号隔离与离线身份

- 沿用现有 `syncSpace`：规范服务器地址 + 实例 ID + 服务端账号 ID 的哈希，不能只用用户名。
- 断网时只访问已确认的当前账号缓存；退出登录立即隐藏个人库及偏好、停止其队列，界面回到原始预置内容。
- 换账号或服务器时移除旧账号结果、详情、编辑器和使用目标；未保存输入先写入旧账号草稿空间，再切换。
- A 的实体、偏好、统计、队列和草稿不能出现在 B 的界面或请求中。未登录／登录失败不凭遗留 `activeSyncSpace` 展示个人内容。
- 令牌失效停止网络重试并要求重新登录；缓存不迁移给新账号，也不转为无账号个人库。

沿用现有 HTTPS、会话鉴权和账号隔离。当前没有端到端加密，服务器管理员可以读取上传的正文；日志与管理后台操作记录不记录正文。

## 7. 数据模型与持久化

以下为已实现的数据模型。预置身份、个人身份和历史身份分开。

### 7.1 PresetCatalog 与 PresetPhrase

目录包含 `catalogVersion`、`locale`、`schemaVersion` 和条目集合。每条预置项包含：

| 字段 | 用途 |
| --- | --- |
| `presetId` | 全局稳定字符串，如 `communication.received`，不会复用 |
| `presetVersion` | 条目内容版本，更新时递增 |
| `title` / `body` / `alias` | 标题、正文、可选检索别名 |
| `categoryKey` / `categoryName` | 稳定分类标识及展示名称 |

预置内容不包含账号 ID、个人置顶、使用次数或隐藏状态。统一资源建议放在 `Resources/quick-phrases.zh-CN.json`，Windows 构建复制同一源文件；升级校验稳定 ID、版本、字段和目录完整性。

### 7.2 PersonalPhrase

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `id` | UUID | 稳定个人 ID，不按正文去重 |
| `title` | string | 必填，去掉首尾空白，最多 80 个 Unicode 标量 |
| `body` | string | 必填，不能全为空白，UTF-8 最多 64 KiB |
| `alias` | string? | 可选，1–32 个 ASCII 字母、数字、`_` 或 `-`；小写存储，不含 `/` |
| `groupId` | UUID? | 当前账号内有效分组；空值表示未分组 |
| `pinned` | bool | 默认 false，同步字段 |
| `originPresetId` | string? | 自定义来源；普通自建／独立副本为空 |
| `originPresetVersion` | integer? | 创建或显式恢复正文所依据的预置版本 |
| `createdAt` / `updatedAt` | UTC timestamp | 服务端赋值；仅使用不更新时间 |
| `revision` | decimal string | 服务端单调修订号；未上传实体为 `"0"` |
| `deletedAt` | UTC timestamp? | 同步删除标记 |

服务端以 `(account_id, id)` 为主键；每账号每个非空 `originPresetId` 最多一个有效个人版本。来源标识只作关联，不授权访问其他用户内容；服务端不强制当前客户端必须识别该预置 ID，以兼容不同目录版本。

正文只统一 CRLF / CR 为 LF，不 trim、不折叠空格。检索大小写及 Unicode 归一化只用于索引，不能回写正文；两端按 Unicode 标量统一校验标题。

### 7.3 分组、预置偏好与限制

个人分组包含 `id`、`name`、时间、`revision` 和 `deletedAt`，名称 1–40 个 Unicode 标量，同账号内不区分英文大小写且唯一。

预置偏好以 `(account_id, presetId)` 为键，保存 `hidden`、`pinned`、修订号和时间。恢复默认偏好仍需同步一个明确版本，不能用本机删除缓存表示恢复。旧客户端遇到未知预置 ID 保留偏好，待相应目录版本可用后应用。

本机统计按 `(syncSpace 或未登录公共范围, 实体类型, 实体ID)` 保存 `useCount` 和 `lastUsedAt`，不上传；个人短语和预置短语不混用 ID。

建议每账号最多 2,000 条有效个人短语、100 个个人分组；预置数量单独管理，不占个人配额。个人短语、分组和偏好容量计入账号用量，超限拒绝操作并保留草稿，不自动删除内容。实际限制由服务端能力接口返回。

### 7.4 本地保存

- 预置资源：只读应用资源，脱离账号及网络仍可使用。
- 个人库：在按空间／epoch 隔离的 SQLite 同步日志中新增实体、偏好、队列、删除标记和游标。实体改动与操作队列同事务提交。
- macOS 由内置 SyncHost 持有个人库，Swift 通过私有管道读取／提交；Windows 直接调用共用组件。界面镜像不作为第二份可写主库。
- 关闭网络同步不关闭本地个人库；统计和草稿按账号空间单独持久化。
- 数据损坏保留原件及有效备份，不把空库覆盖或同步到服务器。历史过期、附件清理不触及短语数据。

## 8. 个人同步与冲突方案

### 8.1 独立实体与变化流

现有 `WireRecord` 只接受文本、链接、图片和文件，按内容哈希合并；`SyncStore` 拒绝改变已有正文。快捷短语需要可编辑内容和按账号的来源关系，因此新增独立协议，复用认证、传输、WebSocket 通知、队列机制和 macOS 私有桥接，不增加历史 `ClipKind`。

| 服务端数据 | 用途 |
| --- | --- |
| `quick_phrases` | 按账号的个人短语、来源、修订及删除标记 |
| `quick_phrase_groups` | 按账号的个人分组 |
| `quick_phrase_preset_preferences` | 按账号的预置隐藏／置顶偏好 |
| `quick_phrase_changes` | 三类实体共用递增变化流 |
| `quick_phrase_operations` | 按账号的操作幂等结果 |
| `quick_phrase_snapshots` | 固定高水位分页快照 |
| `accounts.phrase_sequence` | 与历史及实时剪贴板分开的短语序列 |

个人内容、变更、序号及操作结果同事务写入。删除分组时把所属个人短语移到未分组，并为受影响实体生成变更；离线操作引用已删除分组时返回错误并保留草稿，供选择未分组或新分组。

### 8.2 建议接口

下列接口均位于 `/api/v1`，新服务端提供这些接口；客户端按 `/meta` 声明识别能力。

| 接口 | 行为 |
| --- | --- |
| `GET /meta` 新增能力 | `features.quickPhrases = 1`、支持实体和字段／数量限制 |
| `POST /phrases/operations` | 批量维护个人短语、分组、预置偏好；最多 100 项，带操作 ID、实体 ID、`expectedRevision` 和 `syncEpoch` |
| `GET /phrases/changes?after=…&limit=…` | 按账号返回变更、下一游标、高水位和 epoch |
| `POST /phrases/snapshots` | 创建个人库及偏好的固定高水位快照 |
| `GET /phrases/snapshots/{token}?page=…` | 分页读取当前账号快照 |
| `WSS /events` 新增 `phrases` 通知 | 仅提示个人库变化，客户端拉取；不传正文、不触发粘贴 |

每项独立返回 `accepted / conflict / rejected / deleted` 及必要实体。同一次操作重试返回原结果；来源唯一性冲突返回已有个人版本，客户端保留输入后引导编辑／另存。别名、名称、容量、epoch 错误均有可识别错误码。

快照、变化流、幂等结果和通知均从会话约束账号。普通短语接口不能修改预置原文；第一版官方资源没有用户可写的在线端点。

### 8.3 离线与冲突规则

1. 新增／编辑先本地事务保存并显示待同步；网络失败不丢用户输入。
2. 联网先补齐远端变化，再提交带 `expectedRevision` 的操作；远端版本不能覆盖本机草稿。
3. 同一实体两端同时编辑产生冲突，保留两版；可保留服务器版、以最新修订提交我的版本，或另存独立个人副本。
4. 第一版按整条实体检测冲突，不按设备时间决定最后写入，不自动拼接正文。
5. 删除优先：删除 ID 不接受修改或重新创建，离线草稿只能显式另存新 ID。重复删除幂等；删除关联版本后允许新 ID 再次自定义同一预置。
6. 同账号两台设备同时首次自定义同一预置时，来源唯一约束保留一条关联版本，另一份输入作为冲突草稿，不能静默丢弃。
7. 使用次数不进入同步；可合并尚未上传的同实体操作，已发出操作保留原 ID 与结果对应关系。
8. 变化游标过期时读取固定高水位快照，再从其游标继续拉取；替换服务端镜像保留未提交队列和草稿。
9. 可清理 90 天前的变更，但保留删除 ID 的最小墓碑，防止长期离线设备复活内容；普通历史清理不删除个人短语。
10. 账号偏好同步不修改官方目录；官方更新不作为个人库写操作，不产生批量覆盖。

换账号、退出登录或关闭同步时，请求和异步回调绑定原空间与连接代次，旧结果不能刷新新账号页面。epoch 重置隔离旧队列并保留恢复草稿，不直接回灌。

## 9. 兼容、实现阶段与落点

### 9.1 兼容与发布

- 新客户端连接旧服务器：内置预置可用；不声明短语能力时禁止开启个人云端功能，并提示升级服务器，原历史同步照常运行。
- 旧客户端连接新服务器：新增表和接口不改变原历史协议。
- 预置资源不依赖服务器；个人来源指向当前设备未知预置时，个人正文仍可正常使用。
- 新增协议通过 `/meta` 可选字段声明，短语带独立 schema 版本。
- 追加 schema 并更新数据库版本检查，验证部署回滚是否允许升级后的数据库；不把增加表直接视为旧二进制可回滚的依据。
- 升级不自动把收藏、常用或全量预置复制进个人库。
- 建议先发布服务端个人能力，再发布含共用预置资源与 UI 的两端客户端；真实双设备验收通过后正式发布。

| macOS 视图 | 新增 `Sources/QuickPhrase.swift`、`QuickPhraseStore.swift`、`QuickPhraseView.swift` | 预置／个人合成、搜索、编辑、账号状态与面板 |
| macOS 入口及使用 | `HistoryView.swift`、`ClipHarborApp.swift`、`Shortcuts.swift`、`ClipboardStore.swift` | 从历史保存、快捷键、剪贴板来源与焦点校验 |

第一版包括以下三个阶段：

1. **预置与账号数据**：统一资源、个人协议／存储、账号隔离、离线持久化及能力识别。
2. **管理与使用**：创建、从历史保存、自定义预置、分组、搜索、面板及复制／粘贴。
3. **同步与异常验收**：同账号设备同步、冲突、退出／切换账号、预置更新保护、迁移回滚和真实输入测试。

## 10. 验收标准

| 编号 | 场景 | 必须满足 |
| --- | --- | --- |
| A01 | 首次启动、未登录、断网 | 可搜索和使用内置预置；新建／自定义引导登录 |
| A02 | A 与 B 分别新增个人短语 | 只看到自己的内容，接口不能越权读取或修改 |
| A03 | A 自定义“确认收到” | A 展示个人版本，B 展示官方原文；A 其他设备同步个人版本 |
| A04 | 再次点击同一预置的自定义 | 打开已有个人版本，不重复创建 |
| A05 | 两端同时首次自定义同一预置 | 只有一条关联版本，另一份输入保留为可处理草稿 |
| A06 | 官方升级正文、分类或下架条目 | 原始预置更新，个人版本完整保留；未知来源 ID 不阻止使用 |
| A07 | 恢复预置正文 | 只有用户确认后替换正文和来源版本，保留其他个人字段 |
| A08 | 隐藏／置顶预置，再切换账号 | 偏好仅属于原账号，同账号同步；退出后恢复原始公共视图 |
| A09 | 删除关联个人版本 | 其他设备删除，“全部”按隐藏偏好决定是否重新展示预置 |
| A10 | 中文、emoji、多行、缩进、末尾换行 | 重启后恢复，复制保留正文；上限校验两端一致 |
| A11 | 从历史保存后清空历史／重置常用 | 个人短语及分组不受影响 |
| A12 | 同正文创建多条个人短语、别名重名 | 独立 ID 可分别编辑，个人别名冲突保留输入 |
| A13 | 删除个人分组 | 内容进入未分组，预置分类不受影响 |
| A14 | 全部／我的／预置搜索及排序 | 自定义优先，不重复命中原文；官方原文仍可单独查看 |
| A15 | 仅键盘操作与中文输入法 | 可完成管理和使用；编辑器回车换行，不抢占输入组合 |
| A16 | 自动粘贴开／关及权限不足 | 符合设置，失败保留复制正文，不向错误窗口粘贴 |
| A17 | 重复使用短语 | 不新增本机历史、不累计常用，使用统计每次只加一 |
| A18 | 编辑、下载个人内容或更新预置 | 不覆盖系统剪贴板、不发布实时复制事件 |
| A19 | 主动使用预置／个人，文本同步开／关 | 按原文本规则发布或阻止事件，不影响个人库同步 |
| A20 | 断网新增／编辑，重启后联网 | 内容及队列持久化，补传成功，不补发过期复制事件 |
| A21 | 同一个人短语编辑冲突或删除后离线编辑 | 保留草稿、不静默覆盖、不复活已删除 ID |
| A22 | 退出 A、登录 B、换服务器、旧回调返回 | B 无法看见、搜索、使用或上传 A 的内容／偏好／草稿 |
| A23 | 请求重试、快照分页期间新增、游标过期 | 不重复创建、不漏变更、快照不跨账号 |
| A24 | 旧服务器、新旧客户端及不同预置版本 | 内置内容与原历史可用，个人能力缺失有反馈，个人来源兼容 |
| A25 | 数量／容量超限、磁盘失败或资源损坏 | 不清理个人短语、不丢草稿、不用空数据覆盖有效库 |
| A26 | 两端包的预置资源和服务端升级回滚 | 同一发行版本资源一致，账号及历史保留，schema 检查符合约定 |

性能目标：用 2,000 条代表性个人短语及预置目录验证，已加载列表搜索反馈目标 100 ms 内；正常网络下小体积个人变更目标 2 秒内到达另一在线设备。首次加载不阻塞输入，以目标设备实测确认。

最低验证组合：macOS 本机测试、Windows 核心测试与原生运行、双账号服务端集成测试，以及 Mac ↔ Windows 两台设备真实复制／粘贴。涵盖断网、权限拒绝、账号切换、中文输入法和预置版本变化。

## 11. 已确定方向与待细化项

本次已确定：**我们提供预置短语，用户以自己的账号维护个人内容。** 本文据此采用官方原文只读、个人自定义独立保存、同账号同步和账号偏好隔离。

仍可细化：首批预置分类与具体文案、是否将管理后台在线发布提前到第一版、导入导出优先级，以及数量／正文上限。输入缩写自动替换暂未确定纳入首发。
